Request, verify, and deliver.

On this pageRust SDKHTTP routesRequest context and versionsHandle results, retries, and cancellationInterpret failuresDurability and retention

Use the Rust SDK to bind a request to its approval and verify the signature and signer receipts. The multi-suite API covers DKLS23 and RedPallas.

Rust SDK

The following excerpt assumes an already constructed, authorized SignRequest, a Client, and two pinned signer identities. It is a usage excerpt, not a standalone program.

use std::time::Duration;

let job_id = client.submit_intent(&request).await?;
// Persist request and job_id in application storage here.
let signed = client.wait_intent(
    &request,
    identities,
    Duration::from_secs(180),
).await?;
// Submit to the destination separately after verification.

wait_intent calls poll_intent, which verifies completed signatures and both receipts. A wait timeout does not prove signing failed; poll the same request to reconcile its state.

signing_key(&KeyRequest, identities)

submit_intent(&SignRequest)
Submit the request and check the returned deterministic job ID.
poll_intent(&SignRequest, identities)
Read status, verifying the result when complete.
wait_intent(&SignRequest, identities, timeout)
Poll until complete or failed, within a caller-selected wait bound.
cancel_intent(&SignRequest)
Request cancellation of coordinator work/delivery. This does not revoke Solana authority.
fresh_attempt(&SignRequest, random_id)
Create an explicit retry with a different unpredictable attempt ID. It does not refresh the destination nonce or approval.

Request context and versions

SignRequest binds protocol version, registration, attempt, intent, and backend certificate. The attempt contains the exact COMMIT, a random attempt ID, and authorization. The intent binds its version, enrolled key, and payload. Use exported Rust types rather than hand-assembling cryptographic envelopes.

Multi-suite requests and receipts require protocol version 2. Upgrade workers, coordinator, and SDK together. Old or missing versions are refused; destination key derivation is unchanged.

Handle results, retries, and cancellation

DKLS23 and RedPallas requests use POST /jobs with a signing envelope. Poll GET /jobs/:id, subscribe at GET /jobs/:id/events, or request cancellation through POST /jobs/:id/cancel.

  • Resubmitting the exact request recovers its retained job ID and any completed result. This does not trigger another signing operation while that result remains retained.
  • After a coordinator restart, interrupted jobs fail with may_have_signed: true. They never automatically resume.
  • A fresh attempt is an explicit application decision. Reconcile destination execution before retrying; a new signing attempt does not create a new transaction nonce.
  • Cancellation cannot retract already produced output. Neither can a later session revocation.
  • These durable result guarantees apply to the multi-suite job envelope. The legacy Ed25519 result cache remains memory-only.

The repository guide docs/program-jobs-and-lifecycle.md specifies retention, admission bounds, rate-limit handling, persisted incident latches, and restart semantics.

Interpret failures

Failures include code, error, may_have_signed, and optional retry_after_secs. Interrupted, timed-out, or failed signing may still have produced output. A queued cancellation before work starts can report may_have_signed: false.

For native rate_limited responses, respect the returned delay (currently 61 seconds). Reconcile state before deciding to submit a fresh attempt. The client never automatically retries a destination operation.

Durability and retention

The multi-suite coordinator stores at most 256 retained records, with completed records eligible for removal after 24 hours when admitting new work. After eviction, identical bytes can initiate signing again. Persist verified results in your application.

Single-host file locking and atomic snapshots do not prevent rollback, cloning, or coordination across replicas. Interrupted jobs are failed after restart and never silently resumed.
