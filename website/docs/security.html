What is available?

  • Solana: FROST Ed25519 signing, local transfers, program authorization, constrained sessions and simulation.
  • EVM: DKLS23 ECDSA, local legacy EIP-155 native transfers, and scoped native-transfer sessions. Contract calls, ERC-20, and EIP-1559 adapters are not implemented.
  • Zcash: FROST RedPallas signatures verified through Orchard SpendAuth verification. Transaction assembly, proofs, wallet operations, and end-to-end execution are not implemented.
  • NEAR: Its Ed25519 signature family is compatible with an implemented scheme. A NEAR transaction adapter and end-to-end integration remain planned.
  • Credentials: Service-key and local passkey assertion verification exist. Complete passkey onboarding and OIDC with ephemeral keys remain future work.

Production gates include independent TEE/provider validation, protected entropy, rollback resistance, independent cryptographic review, and root recovery. Local tests do not establish these properties.

“The full private key never exists” describes intended protocol execution: participants create and use separate shares without assembling a full key. It is not a guarantee against extraction of a complete threshold of shares. Thresholds and TEEs have distinct assumptions.

The architecture targets lower authorization overhead through sessions. There is no published apples-to-apples benchmark establishing lower end-to-end cost or latency than NEAR Chain Signatures or Turnkey.

Separate the trust boundaries

  • Solana authority: controller ownership, registry account validation, finalized observations, policy versions, and freshness determine current permission.
  • Signing participants: each party holds its own key share and checks authorization. Two local processes do not demonstrate independent production providers.
  • Relay: coordinates jobs and encrypted MPC transport. It has no authority to grant a signing permission.
  • Destination: transaction parsing, chain IDs, nonces, and execution rules determine where and how a signature can be used.

TEE deployment and recovery

Current workers use private development provisioning files and mock attestation. Release workers refuse startup without a production provisioner. Real attestation, independent deployment governance, protected entropy, authenticated time, independent state sources, and snapshot/rollback defenses remain unverified.

Intact provisioning preserves enrolled keys across ordinary process replacement. Permanent root loss is different: recovery is not implemented. Static roots do not resist sequential extraction of a complete signing threshold.

Nonce and incident lifecycle

Signing nonces are single-use. Cancellation, expiry, and errors discard owned nonce state. Workers persist incident latches across restarts; resetting a backend does not clear a confirmed incident. Investigate and freeze or retire affected authority as appropriate rather than deleting incident files.

Local ownership and clearing do not prove physical memory erasure or protect against restored snapshots. A complete historical signing quorum can sign outside the registry’s current rules.

Read the evidence at the right scope

The saved local gate establishes the exercised software behavior: signature checks, program authorizations, process restarts, refusals, and lifecycle faults. It is not independent cryptographic certification or proof of TEE deployment. Custom key construction and DKLS donor realization/reuse obligations remain specialist review work.

Read the architecture

In the repository, start with docs/program-jobs-and-lifecycle.md, docs/multi-suite-signing.md, and docs/implementation-status.md. Earlier architecture proposals must be read together with the latest implementation evidence.

The comparison on the landing page uses the standard request flow in NEAR’s Chain Signatures documentation and the signing and policy model in Turnkey’s architecture whitepaper. NEAR supports multichain outputs; it is not limited to signing NEAR transactions. Turnkey uses multiple enclave services; it is not accurately described as a single-TEE system.
