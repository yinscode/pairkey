Watch a Solana-controlled permission decide whether two signers can authorize an EVM payment.

Open the interactive demo ↗

Try an allowed payment

  1. Keep the default grant: 0.01 ETH per transfer to Treasury, expiring in 10 minutes.
  2. Select Grant session. The simulated program publishes permission.
  3. Request the default 0.005 ETH transfer to Treasury.
  4. Watch both signer panels check the session, expiration, recipient, and amount.
  5. Read the illustrative receipt. It represents the combined-signature and destination-submission stages; it is not a real transaction.

Explore three refusal cases

  • Too much: select Try too much, then request the transfer. Both signers refuse the amount.
  • Wrong recipient: select Wrong recipient, then request the transfer. The destination address does not match the grant.
  • Revoked or expired: revoke the grant or select Expire now, then request again. The session no longer authorizes signing.

Revoke during the checking animation to see the final authorization check refuse issuance. Reset to clear the demonstration, or grant a new session to try different rules.

What the controls mean

Editing the rule form does not modify the active grant until you select Grant session. Request fields define an individual operation. A fresh grant replaces the simulated session; it is not a production session-ID management API.

The countdown uses your browser clock. Revocation is observed immediately in the simulation; real signers act after observing finalized Solana state. The last successful receipt remains visible after revocation because already issued signatures cannot be recalled.

A simulation, not a signing service

This demo runs entirely in the browser. It creates no private keys, performs no threshold signing, connects to no TEE or chain, and sends no funds. Its fixed animation durations are for explanation, not latency measurements. The four checks illustrate a subset of production authorization requirements.

ETH input uses exact integer wei arithmetic, so a request one wei above its cap is refused. Negative values, scientific notation, and more than 18 decimal places are invalid. The displayed addresses are fixed demonstration fixtures.
