What makes a key programmable?

The source proves each exact request. Optional Solana policy restricts destinations, paths and payloads; a program can add application logic or consume state through an on-chain commit. Both signers independently enforce the current decision.

Why two independent signers?

PairKey distributes signing power across two parties. Each holds a separate key share and independently checks authorization. The protocol produces a signature without assembling the full private key. Read the security model →

How does multichain signing work?

One authorization model connects to FROST Ed25519, DKLS23 ECDSA, FROST RedPallas, and FROST secp256k1. Your application uses the resulting signature with its destination network. Explore chain integrations →

What can I build with PairKey?

Start with a Solana account or program. Integrate passkeys or OIDC identities with bound ephemeral keys. Add persistent rules or state-consuming program approvals when your workflow needs them. Choose your source →
