THE DESIGN PRINCIPLE

The full private key
never exists.

Key shares are created and used separately. The protocol combines signing contributions into a signature, without assembling a complete private key.

What makes a key programmable?

Your application defines who can request a signature, which operations are allowed, and when permission expires. A Solana program governs that authority, and both signers check it before signing.

Why two independent signers?

PairKey distributes signing power across two parties. Each holds a separate key share and independently checks authorization. The protocol produces a signature without assembling the full private key. Read the security model ↗

How does multichain signing work?

One authorization model connects to FROST Ed25519, DKLS23 ECDSA, and FROST RedPallas. Your application uses the resulting signature with its destination network. Explore chain integrations ↗

What can I build with PairKey?

Start with program-controlled payments and scoped delegation. Use exact-operation approvals for individual actions, or time-bounded sessions for repeat operations. Try the program-controlled demo ↗
