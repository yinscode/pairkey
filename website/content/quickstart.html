Run the local program demo

From the PairKey repository root, use Rust 1.88.0 with rustfmt and Clippy, Python 3.12+, and curl. The installer supplies the pinned Solana, Anvil, and SBF tools locally.

python3 scripts/install-ci-tools.py
source .local/ci-tools/env.sh
bash experiments/silence-dkls23/bootstrap.sh build --release --locked
cargo fetch --locked
bash scripts/build-programs.sh
cargo build --workspace --features pairkey-worker/dev-simulation --locked
bash scripts/demo-program-jobs.sh

The demo starts local services, exercises program-authorized signing and EVM sessions, and runs restart, cancellation, and freeze cases. Expect several minutes, including deliberate rate-limit waits. A complete validation gate is available through bash scripts/ci.sh.

Public evidence is written beneath .local/. That directory also contains private development roots and identity material; only selected public reports are suitable for sharing.

What success looks like

The harness exits successfully after completing the program-controlled flows. It starts a local Solana validator, Anvil, two workers, and a coordinator, funds only local accounts, and stops its child processes on exit. Public results include multi-suite signing, EVM transfer execution, session revocation, and the job-lifecycle matrix.

The latest recorded full gate covered 48 host tests, six SBF runtime tests, 15 native invariants, nine native lifecycle tests, and 26 program-controlled process cases. These are saved repository results, not a live status badge for your run.

If the demo refuses to run

  • Missing tools: source .local/ci-tools/env.sh in your current shell after installation.
  • Missing native DKLS source: run the pinned bootstrap before root-workspace Cargo commands.
  • Missing program artifacts: run scripts/build-programs.sh; a host test alone does not compile SBF programs.
  • A deliberate native abort limit: the lifecycle harness may wait 61 seconds before an explicit fresh attempt. Do not weaken the limit to speed up the demo.
  • An incident or ambiguous timeout: inspect the failure and reconcile state. Do not clear incident files or automatically retry a destination transaction.
